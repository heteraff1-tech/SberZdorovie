# Карта работы AI-агента

## Начало задачи

- Работай из корня репозитория; команды npm запускай из `app/`.
- Сначала прочитай задачу, этот файл и относящиеся к изменению документы.
- Проверь `git status`; сохрани чужие правки и не перезаписывай их.
- Определи затронутый сценарий, владельца логики и необходимые проверки.
- Не добавляй API, зависимости или экраны без связи с задачей.

## Карта репозитория

- `app/src/App.vue` — запуск приложения и выбор начального экрана.
- `app/src/pages/` — компоновка экранов и связь событий features.
- `app/src/features/*/model/` — состояние, сценарии и расчёты.
- `app/src/features/*/ui/` — разметка, props, events и scoped SCSS.
- `app/src/features/*/config/` — демонстрационные данные и подписи.
- `app/src/shared/ui/` — переиспользуемые базовые UI-примитивы.
- `app/src/shared/composables/` — подписки браузера и общие жесты.
- `app/src/shared/lib/` — общие функции без зависимости от экрана.
- `app/src/assets/styles/tokens/` — единственный источник токенов стилей.
- `app/public/` — локальные шрифты, пиктограммы и иллюстрации.
- `app/tests/unit/` — расчёты, архитектура, токены и медицинское правило.
- `app/tests/e2e/` — браузерные сценарии, ошибки и мобильная геометрия.
- `app/tests/lib/` — анализ исходников для вычислительных проверок.

## Guardrails: стили

- Single Source of Truth — `app/src/assets/styles/tokens/`.
- В `src/features/` и `src/pages/` запрещены сырые HEX/RGB/RGBA-цвета.
- Цвета бери из `tokens/color.scss`, эффекты — из `tokens/effects.scss`.
- Margin, padding, gap и их логические варианты задавай токенами.
- Допустимы ноль, auto и вычисления от переменных общей шкалы.
- Не создавай локальную переменную, маскирующую произвольный отступ.
- Не расширяй шкалу ради одного значения: используй ближайшее общее.
- Координаты SVG, размеры иллюстраций и физика не являются шкалой отступов.
- Сохраняй снимок Figma; новые прикладные эффекты не выдавай за её переменные.
- Новые токены документируй; не генерируй дополнительные оттенки автоматически.

## Guardrails: UI и архитектура

- Перед новым UI проверь `app/src/shared/ui/` и существующие features.
- Переиспользуй `UiBottomSheet`, `UiButton`, `UiIcon`, `UiIconButton`, `UiTabBar`.
- Не рисуй готовые кнопки или поля целиком SVG-картинкой.
- UI собирается в направлении `shared → features → pages`.
- Направление импортов обратное: `pages → features → shared`.
- `shared` запрещено импортировать `features` или `pages`, включая relative paths.
- `features` запрещено импортировать `pages`; не связывай features напрямую.
- Страница подключает feature через её `index.js`.
- Внутри feature используй относительные импорты и отделяй model от ui.
- Расчёты не должны зависеть от DOM; транспорт API не помещай в UI.
- Кратко описывай назначение публичной функции у её объявления.

## Guardrails: медицинский сценарий

- Правило `HC-001`: высокий пульс с дискомфортом или головокружением.
- Покажи предупреждение, ограничение возможностей и действие обращения за помощью.
- Не ставь диагноз, не назначай лечение и не обещай медицинский результат.
- Контакты экстренной помощи показывай явно; не вызывай их автоматически.
- Поле сообщения, файлы, микрофон и история остаются статичными.
- Сценарий локальный и детерминированный; тесты не обращаются к врачам или LLM.

## Обязательный QA Loop

- После любых изменений кода запускай `npm run qa` внутри `app/`.
- QA последовательно выполняет unit → production build → Playwright.
- При любом падении прочитай сообщение, стектрейс и сохранённый trace.
- Исправь причину и повтори полный `npm run qa` до зелёного статуса.
- Диагностический запуск отдельного теста не заменяет финальный полный QA.
- Запрещено молча обновлять визуальные эталоны или отключать проверки.
- Не используй skip, only, подавление console.error или пустые catch ради зелёного QA.
- Проверяй 375×812, отсутствие горизонтального overflow и reduced motion.
- Не запускай E2E против старой сборки или чужого preview-сервера.
- Если прогон заблокирован окружением, явно сообщи причину и непройденные этапы.

## Завершение

- Обнови документацию вместе с контрактами и функциями.
- Проверь форматирование, `git diff --check` и полный QA после последней правки.
- В отчёте перечисли изменённые файлы, результаты и реальные ограничения.
- Не утверждай, что другие агенты или внешние репозитории проверены без свидетельств.
